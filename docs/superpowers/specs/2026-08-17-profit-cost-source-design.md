# 利润监测成本来源修正设计

## 目标

利润监测不得在上游倍率尚未探测成功时默认按 `1` 计算。新增 API Key 账号应立即触发上游倍率探测；探测结果未确定时，页面不得展示虚假的确定利润。

本设计覆盖 `2026-08-08-profit-monitoring-design.md` 中“倍率最低按 1”和历史保守抬价规则。站内请求计费、账号额度、调度和正常转发行为不变。

## 成本规则

每条使用记录冻结请求发生时的成本来源，不使用查询时的账号或分组当前配置回算历史。

1. 上游探测成功且快照有效：使用请求发生时的上游探测倍率计算成本，来源显示“上游探测”。是否开启“同步上游声明倍率”不影响该选择。
2. 上游明确返回不支持探测：使用该请求最终实际销售额作为估算成本，来源显示“人工估算（按分组倍率）”。因此该记录收入等于成本、利润固定为 `0`。
3. 首次探测尚未完成、探测临时失败、快照过期或探测被关闭：成本状态为“待确认”。该记录保留在待确认数量中，但不进入已确认销售额、成本、利润和毛利率，避免遗漏成本时虚增利润。

“按分组倍率”以使用记录中的最终实际销售额为准，而不是查询账号或分组表的当前倍率。这样可以同时覆盖用户专属倍率、峰时倍率和请求发生后的配置变更。

## 新账号流程

- API Key 账号创建且开启自动探测后，创建接口立即异步触发一次上游倍率探测，不等待最长一分钟的周期任务。
- 创建响应和正常请求不等待探测，避免上游超时或不支持探测导致账号不可用。
- 探测完成前产生的使用记录标为“待确认”，不回退账号默认倍率 `1`。
- 周期探测继续负责刷新快照和失败重试。

## 数据记录与查询

- 使用记录新增不可变成本来源字段，取值固定为 `upstream_probe`、`group_break_even_estimate`、`unknown`。
- `upstream_probe` 同时保存当时有效的上游倍率快照。
- `group_break_even_estimate` 的成本直接使用该记录的 `actual_cost`。
- `unknown` 不产生估算成本，利润聚合将其排除并计入 `unknown_cost_count`。
- 历史无来源记录不自动推断。正式环境通过利润有效起算时间排除已知错误区间，不改写原始使用记录。

## 页面表现

- 摘要和分组、模型、上游账号明细只使用成本已确定或已按平价估算的记录。
- 页面单独显示“成本待确认 N 条”，提醒统计不完整。
- 来源名称使用“上游探测”“人工估算（按分组倍率）”“待确认”，不再展示内部字段名。
- “人工估算（按分组倍率）”必须显示未核验状态，不能冒充上游真实账单。

## 测试

- 新账号创建后立即触发探测，幂等重放不重复触发。
- 有效探测快照使用探测倍率，与倍率同步开关无关。
- 首次待探测、临时失败、过期和关闭探测均记录为待确认，不回退 `1`。
- 明确不支持探测时成本等于实际销售额，利润为 `0`，来源为人工估算。
- 利润汇总、趋势和各维度排除待确认记录，同时正确返回待确认数量。
- 旧记录过滤起点仍使用 UTC 半开区间，不修改历史使用记录。
